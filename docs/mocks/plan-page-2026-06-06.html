Add OAuth redirect handling

Intercept the post-authentication redirect at the gateway, validate the redirect_uri against a configured allowlist, and reject any target that is not explicitly permitted. This closes an open-redirect surface introduced when the provider began echoing arbitrary state back to callers.

Approach

Validation lives in the redirect middleware so every auth flow inherits it without per-route changes. The allowlist is loaded once at boot and refreshed on config change; lookups are exact-host plus path-prefix.

  1. Allowlist config + loader — typed schema, boot-time parse, fail-closed on malformed entries.
  2. Wire validation into redirect middleware — reject with 400 + telemetry on miss.
  3. Tests + telemetry — table-driven host/path cases, counter on rejections.

Risks

  • Open redirect if the allowlist is misconfigured — mitigated by fail-closed parsing.
  • Legitimate redirects broken by an overly strict prefix match — covered by scenario suite.

Out of scope

Token rotation and PKCE migration are tracked separately in TASK-131.
